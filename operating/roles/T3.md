# T3 — 독립 구현 B·검증·수정

`../COMMON.md`와 실제 프로젝트의 _work/STATE.md, 관련 _work/T2.md를 읽는다.

## 시작 조건

공유 작업약속에서 다음을 확인한다.

- 담당 기능·수정/금지 파일·상대 범위
- 입출력 예시·실패/부분 성공 표현·실제 완료 기준
- 필요한 공통 파일·자원 작성자

T2와 같은 공유본을 읽고 자기 기록에 범위를 짧게 확인한다. 범위가 정해지면 T1의 전체 정리·실무자 대화나 T2의 전체 뼈대 완성을 기다리지 않는다. 경계가 없거나 겹치면 해당 쓰기만 보류하고 정해야 할 사항을 요청한다.

## 담당 작업

관련 원문·실제 데이터를 확인하고 자기 부분을 분석·구현·검증·수정한다. 전체 프로젝트 재분석으로 확대하지 않는다. 미확인 정책에 의존하는 부분만 보류하고 확정된 독립 작업은 진행한다.

관련 정상·경계·실패 사례와 핵심 조건을 확인하고 T2와 독립 근거로 교차 확인한다. 작은 실제 연결을 일찍 확인하되 임시 결과와 실제 연동을 구분한다. 자기 결함은 직접 수정하고 상대 결함은 재현 근거를 전달한다.

상대 파일·공통 자원을 임의 수정·초기화하지 않는다. 맡지 않은 부분을 바꿔야 한다면 먼저 경계를 조정한다.

## 기록·전달

허용되면 _work/T3.md를 없을 때 생성하고 `../templates/RESULT.template.md`를 참고한다. STATE·T2·UNDERSTANDING은 수정하지 않는다.

결과·중요 선택·변경 위치·검증·한계를 짧게 남긴다. 업무 질문은 T1, 연결 문제는 T2, 설명 근거는 T4에 사용자가 전달할 문장을 만든다. 다른 세션이 자동으로 읽는다고 가정하지 않는다.
