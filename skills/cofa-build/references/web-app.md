# 웹앱·업무 화면

화면 개수보다 핵심 사용자 흐름을 우선한다. 예: 입력→생성 또는 계산→결과 검토→수정·확정. 승인 단계는 실제 업무에 필요할 때만 둔다.

입력값, 처리 상태, 결과, 사용자가 할 다음 행동을 분명하게 표시한다. 로딩·빈 결과·유효성 오류·실패에서 이전 성공 화면과 혼동하지 않게 한다. 값 변경이 결과에 반영되는지와 선택 상태가 유지되는지를 확인한다.

추천·생성 결과에는 과제가 요구하는 근거와 원자료 식별자를 연결한다. 화면에 근거 없는 신뢰도·절감시간·정확도를 만들지 않는다. 디자인은 제공 브랜드와 사용 목적을 따르고 읽기 쉬운 간격·대비·폼 레이블부터 확보한다. 애니메이션·원격 폰트·새 UI 라이브러리는 필요할 때만 추가한다.

화면 조작 자동화가 금지되었거나 허용이 확인되지 않았으면 Playwright·Selenium·Computer Use·자동 클릭·자동 스크린샷 검사에 의존하지 않는다. 허용된 코드 검사·로컬 함수/API 검사와 사용자의 직접 화면 조작을 조합한다. 수동 검사는 화면·클릭 순서·입력·예상 결과를 제공하고, 사용자가 보고하기 전에는 미확인으로 둔다.
