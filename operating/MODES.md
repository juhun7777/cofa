# 문제를 본 뒤 운영안 하나 선택

세션 수에 정답은 없다. 아래는 준비용 선택지이며 실제 시험 환경에서의 성능이나 사용 가능성을 보장하지 않는다. 각 역할은 `roles/`의 일반 Markdown 문서로 지정한다.

| 운영안 | 적합한 상황 | 활성 역할 |
| --- | --- | --- |
| A: 2세션 | 한 구현자로 처리 가능하고 별도 설명 정리가 유용할 때 | T1 분석·구현·검증 + T3 구현 설명 |
| B: 3세션 | 독립 구현 두 부분과 입출력·파일 범위가 있을 때 | T1 구현 A·통합 + T2 구현 B + T3 구현 설명. T1·T2가 담당 분석·검증 수행 |
| C: 1세션 | 매우 작은 과제, 모델·컴퓨팅 자원 제한, 세션 관리 비용이 더 클 때 | T1이 필요한 분석·구현·검증 수행 |

T1이 먼저 전체 요구·데이터 핵심·실행 구조를 파악하고 작업 경계를 정한다. 모든 분석이 끝날 때까지 다른 작업을 막지 않는다. T2는 지정된 독립 데이터·기존 코드 확인부터 진행할 수 있다. 구현량이 크고 경계가 확보되면 B, 한 구현자로 충분하면 A, 작은 과제는 C로 진행한다. 세 운영안을 전부 실행하지 않는다.

## T2를 추가할 조건

- 분리할 작업의 입력·출력·완료 기준을 한 문단으로 말할 수 있다.
- 담당 소스 파일을 나눌 수 있고, 공통 타입·설정의 작성자를 지정했다.
- T2가 T1의 미완성 결과를 계속 기다리지 않고 실제 작업을 진행할 수 있다.
- 통합에 필요한 조정·재작업보다 병렬화 이득이 클 것으로 판단한다. 근거 없는 시간 절감률을 보장하지 않는다.

입출력이 불명확하거나 같은 핵심 함수를 계속 함께 수정해야 한다면 세션을 늘리기 전에 경계를 정한다. 막힌 알고리즘을 두 명에게 동시에 고치게 하기보다 한 명은 최소 실패 입력·수계산·기준선 비교를 맡길 수 있다.

## 과제별 분리 예시 — 기출·예측 문제가 아닌 일반 예시

| 과제 | T1 — 담당 분석·구현·검증 | B의 T2 — 담당 분석·구현·검증 | T3 — 설명 |
| --- | --- | --- | --- |
| 웹 서비스 | 핵심 처리·API·저장·통합 | 화면·연결 또는 다른 독립 부분 | 실제 모듈·흐름·실패 동작 |
| 알고리즘이 무거운 서비스 | 알고리즘·제약 처리 | API·저장·사용자 기능 | 원리·선택·대안·검증 근거 |
| 데이터 분석·보고서 | 핵심 계산과 결론 | 독립 표·차트·출력 | 계산 근거·해석·한계 |
| 파일 처리·업무 자동화 | 핵심 변환·오류 처리 | 독립 입출력 모듈 | 변환·재실행·부분 실패 |
| 기존 서비스 수정 | 핵심 결함 수정 | 분리 가능한 다른 필수 수정 | 원인·변경·영향 |

작업량과 의존 관계를 보고 나눈다. T2를 무조건 프런트엔드로 고정하거나 과제에 없는 UI·DB를 만들지 않는다.

## 분석·검증의 배분

- 전체 분석: T1이 목적·필수 제약·데이터 핵심·계약의 기준을 잡는다.
- 상세 분석과 기본 검증: T1·T2가 각 담당 기능의 데이터·로직을 직접 분석하고 정상·경계·실패 검사를 수행한다. 발견한 자기 부분 오류는 직접 수정한다.
- 교차 확인: 핵심 계산·필수 제약·인터페이스만 서로 나눠 확인한다. 원문·수계산·별도 기준을 사용하고 제품 로직을 복제해 정답을 만들지 않는다. 서로의 소스를 검토한다고 임의 수정하지 않는다.
- 통합: T1이 전체 흐름을 관리하지만 경계 확인·수정은 담당자가 나눈다. 각자 완성한 뒤 마지막에만 합치지 않는다.
- 설명: T3는 실제 구현·선택 근거·기존 검증 증거를 정리한다. 전체 테스트나 제품 수정은 기본 역할이 아니며 발견한 모순만 담당자에게 전달한다.
- 추가 독립 검사: 필요한 위험에 한해 대상·방법·기대 결과·종료 조건을 정해 한시 배정한다. 미검증은 표시하고 상시 네 번째 세션을 기본 요구하지 않는다.

## 180분 훈련용 흐름

실제 시간·규정·과제 규모가 우선이다. 0~15분 핵심 문서·실행·데이터 확인, 15~30분 핵심 질문·선택·구현 착수, 30~60분 작은 실제 입력의 전체 흐름 연결, 60~120분 필수 요구 완성, 120~155분 검증·수정, 나머지 실행·설명 간극·제출 확인을 목표로 연습한다.

분석이 끝날 때까지 모든 구현을 기다리게 하지 않는다. 아직 모르는 정책에 의존하지 않는 부분은 진행한다. 반대로 정원·권한·배정 같은 필수 정책을 임의 완화해 진행하지 않는다. 검증과 이해 확인은 마지막 구간에 처음 시작하지 않는다.

시간이 부족하면 선택 기능을 먼저 제외한다. 필수 요구 누락은 실패·부분 충족으로 표시하고 남은 시간과 중요도에 맞춰 해결한다. 불확실한 작업 시간 추정만으로 필수 항목을 선택 사항으로 바꾸지 않는다.

## 독립 터미널과 네이티브 서브에이전트

이 자료의 기본안은 사용자가 여러 터미널의 독립 Codex 세션을 운용하는 방식이다. T1이 다른 터미널의 화면에 직접 메시지를 보낼 수 있다고 가정하지 않는다.

시험에서 제공된 버전이 네이티브 서브에이전트를 지원하고 그 사용이 허용된다면, T1에게 범위·담당 파일·완료 조건이 있는 독립 작업만 위임하도록 요청하는 대안도 있다. 실제 하위 에이전트 실행·결과 수집 여부를 확인한다. 역할극 응답만으로 병렬 실행됐다고 판단하지 않는다. 시험 중 설치·업데이트·설정 우회로 기능을 새로 켜는 절차는 포함하지 않는다.
