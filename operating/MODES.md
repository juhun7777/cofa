# 운영안 — 정리 전담과 두 구현자를 우선 분리

2026-11-05 개정. T1 정리·질문, T2 구현 A, T3 구현 B, T4 설명으로 구분한다. 세션 수의 최적성을 보장하는 공식 지침은 아니다.

| 운영안 | 사용할 상황 | 역할 |
| --- | --- | --- |
| B: 4세션 | 구현량이 크고 별도 설명 관리도 필요한 경우 | T1 정리·질문 / T2 구현 A / T3 구현 B / T4 설명 |
| A: 3세션 | 두 구현자는 필요하지만 별도 설명 담당의 부담이 큰 경우 | T1 정리·질문·짧은 설명 / T2 구현 A / T3 구현 B |
| C: 2세션 | 실제 구현이 한 명으로 충분한 작은 과제 | T1 정리·질문·설명 / T2 구현·검증 |

이전에 네 세션을 썼더라도 실제 구현자가 한 명이면 구현 처리량은 늘지 않는다. 현재 B는 역할별 분석/PM/구현/검증을 직렬로 통과시키던 구조와 달리 구현자를 두 명 둔다. 그래도 독립 구현이 불가능하면 세션 수보다 작업 경계를 먼저 정한다.

## 시작과 분리

T1이 단계별로 과제·데이터 핵심·실행 구조를 파악하고 출처 표를 만든다. 사용자는 목적·필수 조건·성공 기준을 함께 확인한다. T2가 제공 스택과 기존 실행 경로를 확인하고 작은 뼈대·공통 입출력을 제안할 수 있다.

T1은 업무 요구·완료 조건·작업 우선순위를, T2·T3는 기술 입출력·파일 경계를 맞춘다. 작은 요청·응답 예시와 담당 파일이 있으면 시작하며 모든 문서·분석 완료를 기다리지 않는다. T3는 뼈대 완성 전이라도 독립된 데이터 처리·모듈·검증 사례를 맡을 수 있다. 미확인 정책을 임의로 확정하지 않는다.

## 분리 기준

- 입력·출력·실패 표현·완료 조건이 명확하다.
- 공통 타입·설정·스키마 작성자를 정했고 제품 파일이 겹치지 않는다.
- 실제로 구현량을 덜어 주는 독립 작업이다. 무조건 백엔드/프런트엔드로 나누지 않는다.
- 각 담당자가 자기 부분을 검증·수정한다. 기술 통합 담당 T2가 모든 오류까지 떠맡지 않는다.

| 과제의 큰 작업 | T2 예시 | T3 예시 |
| --- | --- | --- |
| 웹 서비스 | 핵심 처리·API·저장 | 사용자 기능·화면·연결 |
| 알고리즘 중심 서비스 | 알고리즘·필수 제약 | API·저장·사용자 기능 |
| 데이터·보고 | 핵심 집계·분석 | 독립적인 결과 출력·차트·근거 연결 |
| 파일·업무 자동화 | 핵심 변환 | 입출력·실패 처리의 독립 모듈 |

화면·DB·별도 계층이 필요하지 않으면 만들지 않는다. 같은 핵심 함수를 동시에 고쳐야 한다면 한 명은 구현, 다른 사람은 작은 실패 사례·수계산·비교 기준을 맡는 식으로 조정한다.

## 검증·설명의 배분

- 전체 의미·요구 대조: T1이 출처와 실무자 답변을 확인하고 증거 위치를 취합한다. 모든 테스트를 직접 실행하지 않는다.
- 상세 분석·기본 검사: T2·T3가 자기 범위를 직접 분석·구현·검사·수정한다.
- 교차 확인: 핵심 계산·필수 제약·경계를 서로 나눠 원문·수계산·독립 기준으로 확인한다. 같은 가정을 공유할 가능성을 주의한다.
- 통합: 지정한 기술 통합 담당이 전체 흐름을 연결하되 결함 수정은 소스 담당자가 한다. 작은 실제 흐름을 일찍 연결한다.
- 설명: T4는 코드와 실제 결정·검증 기록을 읽고 UNDERSTANDING을 갱신한다. A·C에서는 T1이 필요한 수준으로 겸한다.
- 추가 독립 검사가 필요하면 대상·방법·기대 결과·종료 조건이 있는 한시 작업으로 배정한다. 미검증은 표시한다.

## 180분 훈련 목표

0~15분 핵심 문서·실행·데이터 구조, 15~30분 중요 질문·작업 경계·뼈대, 30~60분 작은 실제 흐름 연결, 60~120분 필수 완성, 120~155분 검증·수정, 나머지 설명 간극·실행·제출 확인을 목표로 연습한다. 실제 안내·타이머·과제 규모가 우선이다.

T1은 초기에 한 번 정리하고 끝나는 것이 아니라 중요한 실무자 답변·데이터 의미·구현 결과가 바뀔 때 표·결정·영향을 갱신한다. 새 정보 없이 계속 재요약하거나 구현자에게 매번 승인받게 하지 않는다. T4도 변경이 전달된 부분만 갱신한다.

## 독립 터미널과 서브에이전트

기본은 사용자가 독립 Codex 세션에 역할을 주는 방식이다. 파일 갱신만으로 다른 세션이 읽거나 지휘받는다고 가정하지 않는다. 제공 환경이 네이티브 서브에이전트를 지원하고 사용이 허용되면 범위가 명확한 작업을 위임하는 대안도 있다. 설치·업데이트·기능 우회·자동 통신 구축을 전제로 하지 않는다.
