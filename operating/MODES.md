# 운영안 — T1·T2·T3·T4 네 역할로 고정

당일 역할 선택의 혼란을 줄이기 위해 네 세션을 기준으로 사용한다. 특정 과제·알고리즘·기술·산출물 구조를 정하는 문서는 아니다. 네 세션이 모든 문제에서 가장 빠르다고 가정하지 않으며, 각 세션의 실제 작업량은 과제에 맞춘다.

| 세션 | 고정 역할 | 시작 시점 |
| --- | --- | --- |
| T1 | 요구·출처·질문·답변·변경·상태 | 가장 먼저 |
| T2 | 구현 A·작업 분리·통합·담당 검증/수정 | T1의 T2 시작 가능 안내 후 |
| T3 | 독립 구현 B·담당 검증/수정 | 독립 범위·입출력·파일·완료 기준 공유 후 |
| T4 | 실제 결과·선택·검증·한계 설명 | 첫 기능·모듈·작은 실제 결과가 생긴 뒤 |

네 세션을 처음부터 동시에 바쁘게 돌리지 않는다. T1은 전체 정리·실무자 대화 완료를 기다리게 하지 않고 T2·T3의 시작 조건이 갖춰지면 사용자에게 알린다. 실제 세션 실행·전달은 사용자가 한다.

## 작업 분리

T2가 분리 초안을 제안하고 T1이 STATE의 공유 분담으로 취합한다. T2·T3는 담당 기능·수정/금지 파일·입출력·실패/부분 성공·완료 기준과 공통 자원 작성자를 확인한다. 같은 파일을 동시에 수정하지 않는다.

T3에 넘길 독립 구현이 없으면 핵심 결과의 독립 검사·경계/실패 사례·비교 기준 등을 맡긴다. 일을 만들기 위해 기능을 추가하거나 같은 파일을 함께 고치지 않는다. T3는 정해진 범위의 검사 기록을 자기 파일에 남기고 소스 수정은 해당 담당자가 한다.

## 검증·설명·보고

각 구현자는 자기 결과를 검사·수정하고 핵심 조건은 독립 근거로 교차 확인한다. 통합 담당은 기본 T2지만 모든 결함을 대신 고치지 않는다. T1은 원문 요구와 증거를 대조하고 T4는 실제 결과를 설명한다.

T4는 중요한 변경이 전달될 때 관련 부분만 갱신한다. 새 자료가 없으면 반복 조회·문서 확장을 하지 않으며 설명을 구현의 승인 조건으로 만들지 않는다.

사용자는 중요한 판단·실무자 소통·대표 결과 확인·제출을 맡는다. 세션 간에는 새 사실·중요 선택·충돌·연결 준비만 짧게 전달한다. 시간은 사용자가 관리한다.

## 세션 실행

같은 프로젝트에서 별도 Codex 세션에 역할 프롬프트를 입력한다. 터미널 이름만으로 역할·대화가 공유되지는 않는다. 추가 설치·자동 통신 구축 없이 제공 환경에서 진행한다.
