# 문제를 구현·검증 가능한 범위로 정리

현재 단계·남은 시간·허용 도구·제출 조건을 사용자 안내에서 확인한다. AI 금지 단계이면 지원하지 않는다. 시험별 시간·모델·도구 규칙을 이 범용 스킬에서 추정하지 않는다.

주어진 과제·기존 파일·예시 입력을 먼저 읽는다. 이미 명확한 요구사항을 다시 묻지 않는다. 현업 역할의 에이전트가 실제 제공되고 사용이 허용돼 있을 때만 사용자, 현재 업무 흐름, 실패 비용, 우선순위에 관한 구체적 질문을 한다. 질문 자체를 늘리거나 정답·채점 기준을 요구하지 않는다.

다음을 짧게 정리한다.
- 사용자와 해결할 업무 문제.
- 입력→처리→출력, 필수 조건과 제출 방식.
- 필수·선택 요구사항, 각 완료 조건과 확인 방법.
- 결과를 바꾸는 미확인 사항과 근거 없는 가정.

대안은 실제 선택이 필요한 경우에만 최대 두 개를 비교한다. 제공 스택, 첫 작동까지 시간, 검증 난도, 실패 위험을 기준으로 추천한다. 중요한 방향만 사용자가 결정하게 하고 이미 정해진 범위의 구현을 반복 승인으로 막지 않는다.

처음 작동시킬 가장 작은 전체 흐름과 제외할 선택 기능을 정한다. 과거 과제의 도메인·기능을 현재 요구사항에 끼워 넣지 않는다. 기획 산출물은 짧은 표 하나를 기본으로 하고, 긴 PRD나 다단계 승인 절차는 실제 제출 요구가 있을 때만 만든다.

작업 가능한 범위가 정해지면 범위 정리를 끝낸다. 구현·검증을 위한 시간과 제출 여유를 보존한다. 시간은 실제 타이머나 사용자 입력을 기준으로 하고 메시지 수로 추측하지 않는다.
