# 시험 시작 안내 — 정리 T1 / 구현 T2·T3 / 설명 T4

특정 문제·데이터·기술을 예상하지 않는 운영 틀이다. 실제 과제·시험 규칙이 우선이며 시간은 사용자가 관리한다.

## 1. 준비 자료 받기 — 일반 터미널

반입·다운로드가 허용되면 실제 프로젝트 루트에서 한 번 실행한다.

```sh
git clone --depth 1 https://github.com/juhun7777/cofa.git cofa-prep
```

cofa-prep는 자동 생성된다. 원본 과제 README·데이터·소스를 포함하는 기준 위치가 프로젝트 루트다. 탐색기의 선택과 터미널 위치는 다를 수 있으므로 제공 셸의 `pwd`, `ls` 등으로 확인한다. 위치가 불명확하면 첫 세션에 확인을 요청한다. 기존 준비 폴더가 있으면 덮어쓰거나 다시 clone하기 전에 확인한다.

## 2. 세션과 기록

같은 실제 프로젝트 루트에서 제공된 방법으로 Codex를 실행한다. `codex` 명령이 제공되면 사용한다. cofa-prep 안으로 이동하지 않는다. 추가 세션도 같은 프로젝트에서 별도로 실행한다. 아래 역할 문장은 셸 명령이 아니라 Codex 입력이다.

| 역할 | 일 | 허용된 경우 작성할 기록 |
| --- | --- | --- |
| T1 | 요구·출처·질문·답변·변경·상태 | _work/STATE.md |
| T2 | 구현 A·분리 제안·통합·자기 검증/수정 | _work/T2.md |
| T3 | 독립 구현 B·자기 검증/수정 | _work/T3.md |
| T4 | 실제 결과·선택·검증·한계 설명 | _work/UNDERSTANDING.md |

각 작성자가 기록을 없을 때 생성한다. 원본 README·데이터 설명을 대신 수정하지 않는다. 네 세션을 모두 강제하지 않으며 [운영안](MODES.md)을 실제 작업량에 맞춰 선택한다. 준비 지침은 [공통 원칙](COMMON.md)과 역할 파일을 직접 읽어 사용하며 별도 스킬 등록·설치가 필요 없다.

## 3. T1 시작

주요 경로 세 개는 예시다. 알면 실제 위치로 바꾸고, 경로 복사·표시가 없거나 모르면 해당 블록을 지워도 된다. T1이 현재 프로젝트에서 찾고 보여 주게 한다. 경로 때문에 시작을 늦추지 않는다.

```text
현재는 AI 허용 과제 단계다. 시간은 내가 관리한다.
너는 T1 프로젝트 이해·정리·질문 담당이다.
cofa-prep/operating/COMMON.md, cofa-prep/operating/roles/T1.md,
cofa-prep/operating/MODES.md를 읽어 줘.

현재 작업 위치와 실제 과제·규칙·실행·제출 안내를 확인해 줘.
참고할 주요 경로(예시이며 실제 존재·내용을 확인):
- 과제 README: ./README.md
- 데이터 설명: ./data/README.md
- 실제 데이터: ./data/
경로가 다르거나 미확인이면 프로젝트에서 직접 찾고 후보와 용도를 보여 줘.
cofa-prep는 준비 자료이며 실제 과제·데이터와 구분해 줘.

초기 확인은 ①과제·제약·실행·제출 ②데이터 설명과 실제 구조·단위·대표 값·규모·관계·주요 누락/중복 ③관련 기존 코드·파일·작업 절차로 나눠 줘.
긴 자료는 절 단위로 읽고 미확인 범위를 표시하며 매 단계 승인을 기다리지 마.
목적·필수 조건·성공 기준을 먼저 보여 주고,
내용 / 의미·중요성 / 출처 / 확정·추정·미확인 / 구현·검증 영향 / 다음 질문을 표로 정리해 줘.

허용되면 _work/STATE.md를 없을 때 생성하고
cofa-prep/operating/templates/STATE.template.md를 참고해 작성해 줘.
기존 기록은 읽고 갱신하며 STATE는 T1만 작성하고 원본 자료는 보존해 줘.
핵심이 잡히면 T2를 시작할 범위와 전달 문장을 알려 줘.
T2 분리 초안에서 독립 범위가 정해지면 STATE에 취합하고 T3 시작 문장을 만들어 줘.
전체 정리·실무자 대화·전체 뼈대 완성을 시작 조건으로 삼지 마.

초기 요구·데이터 확인·구현/검증 중 필요한 질문을 그때 제시해 줘.
관련 원문을 먼저 확인하고 사실·미확인·답에 따라 달라질 일을 붙여 중요한 질문 1~3개부터 보여 줘.
지금 실무자에게 보낼 중요한 질문은 STATE에만 기록하지 말고 이 대화에도 바로 보여 줘.
내가 복사해서 보낼 질문 문장과 필요한 이유·답에 따라 달라질 일을 짧게 붙여 줘.
새 질문이나 중요한 변경이 있을 때만 알리고 같은 질문을 반복 출력하지 마.
실제 답변이 오면 조건·변경 영향과 관련 세션용 전달 문장을 갱신해 줘.
미확인 정책에 의존하는 부분만 보류하고 독립 작업은 계속해 줘.
제품 구현·전체 검증을 떠맡거나 새 정보 없이 반복 정리하지 마.
```

## 4. T2 주 구현 시작

T1이 핵심 요구를 STATE에 기록하고 시작 범위를 알려 주면 새 세션에 입력한다. 전체 자료 확인을 기다리지 않는다.

```text
너는 T2 주 구현 A·작업 분리·통합 담당이다.
cofa-prep/operating/COMMON.md와 cofa-prep/operating/roles/T2.md,
_work/STATE.md를 읽어 줘.
실제 기존 파일·실행/작업 절차·활용할 부분·미구현을 짧게 확인해 줘.
T3와 나눌 기능·수정/금지 파일·입출력 예시·실패/부분 성공·완료 기준과 공통 자원 담당자를 제안해 줘.
허용되면 _work/T2.md를 생성해 초안을 남기고 T1용 전달 문장을 만들어 줘.
STATE의 공유 분담을 확인한 뒤 자기 범위를 구현·검증·수정해 줘.
전체 정리·실무자 답변·전체 뼈대 완성을 기다리지 말고 T3가 일찍 시작할 범위를 제시해 줘.
작은 실제 입력으로 일찍 연결하고 상대 담당 파일은 임의 수정하지 마.
중요 선택 이유·대안/한계·변경 위치·검증 근거를 자기 기록에 남겨 줘.
```

기존 구조 확인은 실행/작업 방법·이미 제공된 기능·미구현을 찾아 재사용과 작업 분리를 정하는 일이다. 전체 코드 정독이나 새 구조 구축을 뜻하지 않는다. 코드·기능이 없으면 그 사실에 맞춰 필요한 최소 산출물을 계획한다.

## 5. T3 두 번째 구현 시작

T2의 초안을 T1이 STATE의 공유 분담으로 취합한 뒤 입력한다. 기능·파일·입출력·실패 표현·완료 기준이 정해진 독립 범위부터 시작한다.

```text
너는 T3 독립 구현 B 담당이다.
cofa-prep/operating/COMMON.md와 cofa-prep/operating/roles/T3.md,
_work/STATE.md와 관련 _work/T2.md를 읽어 줘.
최신 공유 작업약속의 자기 기능·수정/금지 파일·입출력·실패 표현·완료 기준과 공통 자원 담당자를 확인해 줘.
허용되면 _work/T3.md를 생성해 읽은 ID와 범위를 짧게 남겨 줘.
독립 범위가 정해지면 전체 정리·실무자 대화·전체 뼈대 완성을 기다리지 말고 진행해 줘.
미확인 정책에 의존하는 부분과 겹치는 쓰기만 보류하고 확인해 줘.
자기 분석·구현·검증·수정을 수행하고 작은 실제 연결과 핵심 조건의 교차 확인을 해 줘.
상대 파일·공통 자원은 임의 수정하지 말고 선택·변경·검증·한계를 자기 기록에 남겨 줘.
```

## 6. T4 구현 설명 시작 — 필요할 때

첫 기능·모듈·작은 실제 결과가 생기면 시작한다. 전체 완성을 기다리지 않는다. 설명을 T1이 겸할 수 있으면 별도 세션을 생략한다.

```text
너는 T4 실제 결과·선택·검증·한계 설명 담당이다.
cofa-prep/operating/COMMON.md와 cofa-prep/operating/roles/T4.md,
_work/STATE.md, _work/T2.md, _work/T3.md와 관련 실제 산출물·코드를 읽어 줘.
첫 기능·작은 결과부터 목적·실제 위치·처리 흐름·핵심 원리·선택 이유·대안·한계·검증을 설명해 줘.
허용되면 _work/UNDERSTANDING.md를 생성하고
cofa-prep/operating/templates/UNDERSTANDING.template.md를 참고해 그 파일만 관리해 줘.
중요 기능·방식·정책·연결·검증이 바뀌었다고 전달받으면 해당 부분만 갱신해 줘.
기록에 없는 의도·사용자 이해·실행하지 않은 검증은 지어내지 마.
제품 파일·다른 기록을 수정하거나 전체 검증을 떠맡지 마.
자동 감시·중복 요약을 하지 말고 설명을 구현 진행의 승인 조건으로 삼지 마.
```

## 7. 중요한 변경만 전달

세션 사이의 전달은 자동이 아니다. 아래 문장을 필요한 때 사용한다. W1은 첫 공유 분담의 예시이며 경계·계약이 바뀌면 관련 세션에 새 ID와 변경을 전달한다.

T2 초안 → T1:

```text
_work/T2.md의 분리 초안을 원문 요구와 대조해 줘.
독립 범위를 STATE에 공유 작업약속 W1로 취합하고,
T2·T3에 각각 전달할 시작 문장을 만들어 줘.
미확인 정책이 영향을 주는 부분은 따로 표시해 줘.
```

분담 확정 → T2·T3 각각:

```text
STATE의 공유 작업약속 W1을 읽고 자기·상대 범위와 공통 파일 담당,
입출력·실패 표현·완료 기준을 확인해 줘.
정해진 범위는 진행하고 겹치는 쓰기만 확인해 줘.
```

실무자 답변 → T1:

```text
실무자의 실제 답변이야: [답변 붙여넣기]
확정·미확인·남은 가정과 요구/구현/검증 영향을 STATE에 갱신하고,
관련 세션에 전달할 짧은 문장을 만들어 줘.
```

관련 변경 → 구현자:

```text
STATE의 변경 조건과 최신 공유 작업약속을 읽고 자기 부분에 반영해 줘.
연결 문제는 재현 근거와 함께 해당 파일 담당자에게 전달해 줘.
```

중요 결과·선택·검증 변경 → T4:

```text
T2·T3 기록과 관련 실제 산출물·코드의 최신 변경을 확인해 줘.
이번 기능의 흐름·선택 이유·검증·한계를 설명하고
UNDERSTANDING에서 영향받는 부분만 갱신해 줘.
```

## 8. 검증·마무리·제출

T2·T3는 자기 작업을 확인·수정하고 작은 실제 입력의 전체 흐름을 일찍 연결한다. 핵심 조건은 원문·원자료·수계산 등 독립 기준과 비교한다. T1은 요구와 증거를 대조하며 모든 검사를 재실행하지 않는다. 사용자는 중요한 결과를 직접 확인한다.

마무리 전환 때 관련 세션에 보낸다.

```text
이제 선택 기능 추가보다 필수 누락·오류·실행·제출 확인을 우선해 줘.
실제 완료·부분 충족·미검증·미구현을 구분하고,
필요한 수정과 재검증은 각 담당자가 수행해 줘.
```

T4에는 최종 설명과 실제 결과의 일치를 확인하게 한다. 사용자는 실제 제출 방법·대상·저장·반영 여부를 확인한다. AI의 완료 보고만으로 제출 완료라고 판단하지 않는다. 후속 단계의 AI·자료 열람 규칙을 따르며 금지 시 진행 중 지원도 중단한다.

## 9. 시험 시작 직후부터 제출까지 — 사용자 실행 시뮬레이션

| 순서 | 사용자가 할 행동 | 다음 단계의 기준 |
| --- | --- | --- |
| 1 | 시험 안내·프로젝트 위치 확인, 허용된 경우 clone 한 번 | 준비 폴더와 실제 프로젝트 구분 |
| 2 | 제공 Codex에서 3절 T1 프롬프트 입력 | 핵심 요구·성공 기준이 STATE에 기록됨 |
| 3 | 중요한 원문을 직접 보고 T1 질문을 실무자에게 전달 | 답을 T1에 주고 필요한 조건 갱신. 질문은 진행 중에도 계속 |
| 4 | 새 세션에서 4절 T2 프롬프트 입력 | 재사용·미구현 확인과 독립 작업 분리 초안 |
| 5 | T1에 초안을 읽고 공유 분담을 취합하게 함 | 기능·파일·입출력·실패·완료 기준 확정 |
| 6 | T2에 분담 확인 전달, 새 T3에 5절 프롬프트 입력 | 같은 공유본의 독립 범위에서 병렬 진행 |
| 7 | 첫 결과가 생기면 필요할 때 6절 T4 시작 | 실제 결과·선택·한계를 본인이 설명할 수 있도록 확인 |
| 8 | 중요한 답변·계약·연결·결과 변경만 관련 세션에 전달 | 작은 실제 흐름 연결과 담당별 검증·수정 |
| 9 | 본인이 마무리 전환 지시, 요구·실행·설명 대조 | 실제 완료와 미검증을 구분 |

독립 작업이 없으면 T3를 검사·비교 등으로 조정한다. 경로·자료 접근이 막히면 필요한 파일·정보를 구체적으로 확인하고, 세션이 과거 조건을 사용하면 STATE 변경 위치를 다시 읽게 한다. 문서·설명이 커지면 새 사실·중요 근거만 남기게 한다.
