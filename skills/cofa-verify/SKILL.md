# 예상 결과와 실제 결과를 대조

현재 AI 사용이 허용되는 단계인지, 검사 방법·파일 접근·외부 통신의 허용 범위를 확인한다. AI 금지 단계에서는 검사·설명도 수행하지 않는다.

과제의 필수 요구사항을 입력과 관찰 가능한 결과로 바꾼다. 기존 테스트를 활용하고 가장 위험하거나 누락되기 쉬운 조건을 우선한다. 모든 사소한 변경마다 전체 검사를 반복하거나 전면 TDD를 강제하지 않는다.

예상 결과는 요구사항·원자료·명확한 업무 규칙·작은 수계산에서 얻는다. 구현 로직을 그대로 복사한 정답, 모델의 자신감, 목업의 성공만으로 검증하지 않는다. 계산이 맞는 것과 업무 목적에 맞는 것은 구분한다.

실제 과제에 맞는 정상 사례와 실패·경계 사례를 고른다. 빈 입력, 잘못된 값, 중복, 외부 실패, 재실행, 원자료와의 불일치 중 결과에 중요한 것만 확인한다. 허용된 로컬 명령과 함수·데이터 검사를 먼저 실행한다. 화면 자동조작은 사용하지 말고 수동 확인 절차를 제공한다.

다음 비교표에 실제 관찰만 남긴다.
| 요구사항 | 입력·재현 조건 | 예상 결과·근거 | 실제 결과 | 명령·파일·위치 | 확인 주체 | 상태 |
|---|---|---|---|---|---|---|

확인 주체는 AI 실행 또는 본인 직접 확인으로, 상태는 미실행·통과·실패·부분 확인으로 구분한다. 사람이 아직 화면을 조작하지 않았으면 본인 직접 확인으로 기록하지 않는다. 명령 출력과 종료 코드를 읽고, 테스트 통과를 요구사항 전체 충족으로 확대하지 않는다.

오류 수정 후에는 원래 실패한 조건을 다시 확인하고 변경이 영향을 줄 인접 조건만 추가 확인한다. 해결되지 않은 실패·목업·미검증을 분리해 보고한다. 사용자가 직접 확인할 때는 화면 위치, 입력, 조작 순서, 예상 결과를 짧게 제공한다. 제출 직전에는 실제 실행·출력·필수 기능·제출 조건을 확인하고 관련 없는 개선은 멈춘다.
