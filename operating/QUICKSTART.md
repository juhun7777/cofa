# 빠른 시작 — 지침을 내려받고 필요한 역할만 읽기

처음 보는 제한 시간 과제의 준비용 운영 안내다. 공식 시험 지침·기출·완성 솔루션이 아니다. 실제 문제를 본 뒤 운영안을 선택하며 점수·완성도·호환성을 보장하지 않는다.

## 준비 자료의 구성

```text
cofa-prep/                    ← 내려받은 일반 지침, 실제 프로젝트와 구분
  operating/
    QUICKSTART.md             ← 사람의 사용 순서
    COMMON.md                 ← 모든 세션이 읽을 공통 원칙
    MODES.md                  ← A 2세션 / B 3세션 / C 1세션
    QUESTIONS.md              ← 필요할 때 T1이 참고할 질문·이해 점검 틀
    roles/T1.md               ← 요구·질문 창구 + 주 구현·통합
    roles/T2.md               ← 분리 가능한 보조 구현
    roles/T3.md               ← 현재 구현의 위치·원리·이유를 정리하는 설명 담당
    templates/                ← STATE와 역할 결과의 빈 양식
  skills/                    ← 기존 선택형 스킬, 자동 설치되지 않음

실제 프로젝트/
  기존 README·데이터·소스
  _work/                      ← 허용될 때 쓰는 실제 기록, 경로는 변경 가능
    STATE.md                  ← T1만 갱신
    T2.md                     ← B에서 T2만 갱신
    UNDERSTANDING.md          ← T3만 갱신하는 구현 설명
```

내려받은 준비 폴더 안에서 앱을 새로 만들거나 실제 기록을 작성하지 않는다. `_work`가 이미 쓰이는 경로라면 별도 경로를 정한다. 새 문서가 제한되면 제공된 허용 기록 방식을 따른다.

## 1. 파일 가져오기 — 셸에서 실행

공개 저장소 다운로드가 허용되고 Git이 제공될 때, 실제 작업공간의 허용된 위치에서 빈 대상 이름으로 한 번 실행한다. 기존 프로젝트를 초기화하거나 기존 폴더에 덮어쓰지 않는다.

```sh
git clone --depth 1 https://github.com/juhun7777/cofa.git cofa-prep
```

이 명령은 준비 자료를 내려받는다. 시험 문제·데이터·작업 결과를 외부에 올리는 명령이 아니다. Git·반입이 막혀 있으면 실제 안내를 따르며 우회·설치·외부 AI 사용을 시도하지 않는다.

ZIP을 받은 경우 `cofa-operating-kit.zip`을 허용된 위치의 `cofa-prep` 폴더로 압축 해제해 같은 구조인지 확인한다. 기존 `cofa-skills-public-candidate.zip`에는 이 operating 안내가 없다.

## 2. Codex 세션 실행 — 실제 프로젝트 루트에서

같은 프로젝트 루트의 터미널에서 시험이 제공한 방법으로 Codex를 실행한다. 환경에서 `codex` 명령이 제공된다면 다음과 같다.

```sh
codex
```

새 터미널도 실제 프로젝트 루트인지 확인한다. 아래 역할 지정 문장은 Codex가 실행된 뒤의 입력창에 넣는 프롬프트다. PowerShell·Bash에 명령처럼 입력하지 않는다. 제공 버전의 모델·추론 수준 선택을 사용하며 별도 설치나 업데이트를 전제하지 않는다.

## 3. T1 시작 — 공통 내용을 길게 복사하지 않고 파일을 읽게 하기

아래는 준비 폴더가 프로젝트 안의 `cofa-prep`, 기록 폴더가 `_work`인 예시다. 실제 경로가 다르면 바꾼다.

```text
현재 단계: [연습 / AI가 허용된 과제]. 실제 남은 시간: [분], 종료 시각: [시각·시간대].
실제 프로젝트 루트: [경로]. 준비 지침 폴더: [경로]/cofa-prep.
실제 허용 도구·제출 조건: [현재 안내 또는 규칙 파일].

너는 T1이다. cofa-prep/operating/COMMON.md와
cofa-prep/operating/roles/T1.md를 실제로 읽어 적용해 줘.
cofa-prep/operating/MODES.md를 참고해 작업량과 의존 관계를 파악하고
A/B/C 중 적절한 안을 추천해 줘. 고정된 세션 수를 강제하지 마.
기존 과제 README·데이터 설명·실행·제출 안내를 읽고 사실·미확인·제안을 구분해 줘.

먼저 업무 목적, 입력→처리→출력, 필수 조건과 원문 근거, 성공 판정,
중요한 실무자 질문, 작은 전체 흐름의 구현 순서를 간결하게 정리해 줘.
실무자에게 질문할 업무 규칙과 코드에서 확인할 동작은 구분해 줘.
중요한 방향은 내가 판단하도록 설명하고, 결정한 범위의 통상 작업은 계속 진행해 줘.

실제 기록은 허용될 때 _work/STATE.md 하나로 취합하고 원본 README를 덮어쓰지 마.
구현을 나눌 때 T1·T2의 기능·파일·입출력·실패 표현·완료 기준을 먼저 정해 줘.
각자 담당 분석·검증·오류 수정을 맡고 중요한 조건은 서로 교차 확인해 줘.
설명 담당 T3에는 결정 근거·변경 파일·기존 검증 위치를 전달해 줘.
필요한 역할의 짧은 시작 프롬프트도 만들어 줘.
다른 터미널을 자동으로 지휘할 수 있다고 가정하거나 자동 통신 프로그램을 만들지 마.
```

읽은 파일·실제 프로젝트 루트·선택한 역할을 짧게 확인하게 한다. 파일이 없으면 역할을 적용했다고 주장하지 말고 경로를 고친다.

## 4. 설명 담당 T3 시작 — 별도 Codex 입력창

```text
너는 T3 구현 설명 담당이다. 실제 프로젝트 루트: [경로]. 준비 폴더: [경로]/cofa-prep.
현재 단계·남은 시간·허용 도구: [내용].
cofa-prep/operating/COMMON.md와 cofa-prep/operating/roles/T3.md를 읽어 줘.
실제 프로젝트의 _work/STATE.md, T2.md가 있으면 관련 부분과 실제 코드를 읽어 줘.

무엇을 만들었는지, 어디에 있는지, 입력→처리→출력과 핵심 원리,
확인된 선택 이유·대안·한계·기존 검증 근거를 설명해 줘.
기록에 없는 이유는 지어내지 말고 추정 또는 확인 질문으로 표시해 줘.
제품 소스와 다른 담당자의 기록은 수정하지 마.
설명은 _work/UNDERSTANDING.md 하나에 정리하고 중요한 변경을 전달받을 때 갱신해 줘.
전체 테스트나 예상 문제 생성보다 내가 현재 구현을 이해하도록 돕는 데 집중해 줘.
```

T3는 초기에는 확인된 목적·조건·모듈 개요만 정리한다. 구현이 생기면 관련 부분을 갱신한다. 자동 감시·반복 조회를 하지 않는다. T1·T2는 자기 부분을 분석·구현·검증하고 중요한 계산·조건을 교차 확인한다. T3의 설명은 실행 검증을 대신하지 않는다.

## 5. B에서 구현 B 담당 T2 시작

T1이 입력·출력 예시와 담당 파일을 정한 다음, 별도 터미널의 Codex 입력창에 넣는다.

```text
너는 T2다. 실제 프로젝트 루트는 [경로], 준비 폴더는 [경로]/cofa-prep다.
현재 남은 시간은 [분]이며 운영안은 B다.
cofa-prep/operating/COMMON.md와 cofa-prep/operating/roles/T2.md,
실제 프로젝트의 _work/STATE.md를 읽어 적용해 줘.

이번 구현: [독립적인 필수 기능]. 수정할 파일: [경로].
입력·출력과 실패 표현: [STATE의 계약 위치]. 완료 조건: [실제 연결·확인 기준].
공통 타입·설정 등 지정하지 않은 파일은 임의 수정하지 마.
담당 부분을 직접 분석하고 구현한 뒤 정상·경계·실패를 검증하고 오류를 수정해 줘.
중요한 계산·필수 조건·인터페이스는 T1과 범위를 나눠 교차 확인해 줘.
결과·실행 증거·질문 후보·선택 이유는 _work/T2.md에 남겨 줘.
T3가 설명서를 갱신할 변경 파일·함수·이유·기존 검증 위치를 전달해 줘.
```

## 6. 질문·진행·인수인계

- T2 → T1: “`_work/T2.md`에 검사 V1과 질문 Q2를 기록했다. 근거를 읽고 업무 질문·수정 우선순위를 정해 줘.”
- T1/T2 → T3: “변경 파일·핵심 함수는 [위치], 선택 이유와 검증 근거는 [기록]이다. 해당 코드와 근거를 읽고 UNDERSTANDING을 갱신해 줘.”
- T3 → T1: “UNDERSTANDING에 선택 이유 미확인 또는 코드 모순을 기록했다. 관련 담당자와 확인해 줘.”
- 실무자 → T1: “실무자 실제 답변: [그대로 또는 의미가 보존된 내용]. 확정 조건과 남은 가정, 영향받는 구현·검증을 갱신하고 다른 역할에 전달할 문장을 만들어 줘.”
- T1 → T2: “`_work/STATE.md`의 계약·질문 Q2가 바뀌었다. 관련 부분을 다시 읽고 담당 파일에만 반영해 줘.”
- 구현 이해: “현재 실제 구현 한 가지를 설명하고 사례 질문을 한 개 내 줘. 내가 먼저 답하게 해 줘.”

문서 갱신만으로 다른 세션이 읽었다고 가정하지 않는다. 사용자가 중요한 변경 시점에 짧은 메시지를 전달한다. 진행 보고는 새 사실·막힌 지점·다음 행동 중심으로 하며 장문 문서와 반복 점검을 늘리지 않는다.

## 7. 기존 스킬·AGENTS와의 관계

이 운영안은 일반 Markdown 역할 지침을 직접 읽는 방식으로 쓸 수 있어 스킬 등록이 필수는 아니다. scope·build·verify·debug는 해당 작업이 필요할 때만 선택적으로 읽는다. 역할 문서 자체는 `$T1` 같은 등록 스킬이 아니다.

`AGENTS.md`는 일반 Codex에서 자동 발견되는 프로젝트 지침 파일이다. 하지만 `COMMON.md`, `roles/T1.md`, `AGENTS.template.md`는 이름만으로 자동 적용되지 않는다. 위 프롬프트로 직접 읽게 하면 된다. 기존 시험 AGENTS를 덮어쓰거나 전역 설정·등록을 바꾸지 않아도 된다.

## 8. 사용 범위와 공식 참고

이 저장소에는 일반 지침과 빈 양식만 둔다. 실제 문제·CSV·실무자 대화·의사결정·결과·서술형을 올리지 않는다. 과제와 후속 단계의 도구·자료 허용 규칙을 따르며 금지 단계에서는 AI 지원을 중단한다.

- 일반 Codex 지침 발견: https://learn.chatgpt.com/docs/agent-configuration/agents-md
- 일반 Codex 서브에이전트: https://learn.chatgpt.com/docs/agent-configuration/subagents

문서의 역할 배치와 시간표는 개인 준비 제안이다. 공식 문서가 특정 시험에서 이 구성을 최적이라고 보증하는 것은 아니다.
