# T2 — 주 구현 A·작업 분리·통합

`../COMMON.md`와 실제 프로젝트의 _work/STATE.md를 읽는다. 요구된 산출물과 기존 환경을 확인하며 특정 기술·구조를 가정하지 않는다.

## 초기 확인과 분리

실행/작업 방법, 관련 기존 파일·기능, 활용할 부분, 미구현·기존 문제를 짧게 확인한다. 코드가 없으면 그 사실을 기록한다. T1의 전체 정리·실무자 대화 완료를 기다리지 않는다.

T2·T3가 나눌 기능·수정/금지 파일·입출력 예시·실패/부분 성공·완료 기준·필요한 공통 자원 작성자를 제안한다. 초안은 T2.md에 남기고 T1이 STATE에 취합하도록 사용자용 전달 문장을 만든다. 전체를 혼자 구현한 뒤 T3를 부르지 않는다.

## 구현·검증·연결

공유 작업약속과 자기/상대 범위를 확인한 뒤 담당 부분을 분석·구현·검증·수정한다. T3가 독립 작업을 할 수 있으면 전체 뼈대 완성을 기다리게 하지 않는다. 미확인 정책에 의존하는 부분만 표시·보류한다.

작은 실제 입력으로 결과 흐름을 일찍 연결한다. 관련 정상·경계·실패 사례를 확인하고 핵심 조건은 T3와 독립 근거로 교차 확인한다. 결과는 입력·기대와 근거·실제·검증 상태를 남긴다.

통합 담당이어도 모든 결함을 대신 고치지 않는다. 상대 파일 오류는 재현 근거를 전달하고 담당자가 수정한다. 공통 경계·자원 변경은 조정 후 반영한다.
